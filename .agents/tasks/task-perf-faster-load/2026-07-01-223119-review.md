# Load performance improvements: font preload, cache headers, chunk splitting, image lazy loading

Four targeted changes reduce initial load time for the `artifacts/electron` SPA deployed to Netlify/Vercel: preload font CSS earlier, make content-addressed assets immutably cacheable, split large vendor libraries into their own chunks so repeat visits skip them entirely, and defer quiz images from the main thread. Watch for: the font preload hint fires a request but doesn't apply the stylesheet — browsers may warn about unused preloads; the `framer-vendor` guard has a dead condition that could silently misroute a `motion`-named transitive dep; and the `/*.js` cache rule could pin `sw.js` at an immutable 1-year TTL, breaking service worker updates.

## High-level view

The font preload positions a `<link rel="preload" as="style">` before the existing `<link rel="stylesheet">` for Google Fonts. The fetch is parallelized but the apply isn't — the stylesheet still blocks at parse time — and Chrome will emit an "unused preload" warning if the paired stylesheet link doesn't consume the preloaded resource within ~3 seconds.

The cache headers set a 1-year immutable TTL on hashed assets across both Netlify and Vercel. The `/assets/*` glob covers all Vite-emitted chunks. The additional `/*.js` and `/*.css` rules don't cover app assets (Vite puts those in `assets/`), but they do cover root-level files — including `sw.js` — where an immutable TTL would break SW update delivery.

The chunk split adds `react-vendor` (React + ReactDOM, ~59 kB gzip) and `framer-vendor` (framer-motion + motion, ~40 kB gzip). On repeat visits with warm cache, these two chunks will be served from cache when only the app chunk changes. The `framer-vendor` guard contains a dead condition — `!id.includes("node_modules/motion-vendor")` — because chunk names don't appear in module file paths. The real guard is `id.includes("node_modules/motion")`, which works today but could silently capture unintended transitive deps.

Quiz photo lazy loading adds `loading="lazy"` and `decoding="async"` to all three quiz image elements. The most meaningful impact is in `ImageOptionsSummary` in the editor panel, which renders all option thumbnails simultaneously and could otherwise hit the browser's decode queue.

### Font preload: fetch parallelization without apply acceleration

The preload tag fires the Google Fonts CSS request as soon as the browser's preload scanner sees it, before the HTML parser reaches the `<link rel="stylesheet">` a line below. The two tags make parallel requests for the same URL; browsers that deduplicate serve from preload cache, but the stylesheet still blocks rendering at parse time. The net risk is a "preload was used, but not consumed" warning in Chrome DevTools, because the preload hint and the stylesheet link refer to the same URL but the browser may not recognize them as paired. Neither behavior is a regression from baseline.

The non-blocking pattern that avoids this is:

```html
<link rel="preload" as="style" href="..." onload="this.rel='stylesheet'" />
<noscript><link rel="stylesheet" href="..." /></noscript>
```

This turns the preload itself into the stylesheet apply on load, eliminating the duplicate request and the warning.

### `framer-vendor` chunk guard correctness

```ts
if (
  id.includes("node_modules/framer-motion") ||
  (id.includes("node_modules/motion") && !id.includes("node_modules/motion-vendor"))
) {
  return "framer-vendor";
}
```

`id` is an absolute file path like `/abs/path/node_modules/motion/dist/...`. The string `node_modules/motion-vendor` will never appear in any real module path — chunk names are computed output names, not input paths. The gsap guard (`id.includes("node_modules/gsap")`) already handles gsap independently. The second branch of the framer-vendor condition just needs to be `id.includes("node_modules/motion")`.

### Service worker cache header exposure

In Netlify, response headers are applied to matched paths before redirects execute. This means the `/*.js` rule applies to `/sw.js` before the `[[redirects]] from = "/*"` SPA fallback can redirect it. A 1-year immutable header on a service worker means browsers that cached the SW after one visit will never re-fetch it, regardless of SW file changes. Vercel processes `headers` before `rewrites` with the same result. The `/assets/*` rule alone is sufficient for all Vite-chunked output. Adding this before the `/*.js` rule closes the gap:

```toml
[[headers]]
  for = "/sw.js"
  [headers.values]
    Cache-Control = "no-cache"
```

### Quiz image lazy loading scope

`loading="lazy"` is most impactful in `ImageOptionsSummary` in `QuestionEditorPanel`, which renders all option thumbnails at once. In `ImageChoiceQuestionView`, images appear one question at a time inside an already-lazy-loaded modal, so the browser's native lazy load behavior adds a second layer of deferral on top of the existing code-split boundary. `decoding="async"` in both locations moves decode work off the main thread, which matters most in the editor panel where multiple images decode simultaneously.
