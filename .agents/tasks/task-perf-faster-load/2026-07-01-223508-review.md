# Load performance improvements: font preload, cache headers, chunk splitting, image lazy loading (v2)

This pass re-examines the three blocking concerns flagged in v1: the font preload pattern, the dead `motion-vendor` guard in vite.config, and the service worker being pinned by the `/*.js` immutable cache rule. All three are fixed. Watch for: the `framer-motion` guard now uses a bare `id.includes("node_modules/motion")` without a trailing slash, which could match a package like `@emotion/motion` — low risk today, but inconsistent with the stricter delimiter pattern used for the `react-vendor` guard in the same block.

**Verdict**: APPROVED

## High-level view

The font preload in `index.html` now uses `onload="this.rel='stylesheet'"` with a `<noscript>` fallback, eliminating the duplicate request and the unused-preload DevTools warning. The standalone `<link rel="stylesheet">` is gone.

The dead `!id.includes("node_modules/motion-vendor")` condition is removed from vite.config. The remaining guard is correct for the current dep set, and a comment was added explaining why the exclusion was unnecessary. A bare `motion` substring match without a trailing slash or word boundary remains, inconsistent with the `/node_modules/react/` pattern used one line above.

The service worker cache gap is closed in both deployment configs. `netlify.toml` places the `/sw.js` no-cache rule before `/*.js`. `vercel.json` places `/sw.js` before `/(.*\.js)`. Both platforms evaluate header rules top-to-bottom, so the explicit no-cache rule wins.

### `framer-vendor` guard: dead condition removed, mild delimiter gap remains

The simplified condition:

```ts
if (
  id.includes("node_modules/framer-motion") ||
  id.includes("node_modules/motion")
) {
  return "framer-vendor";
}
```

The comment accurately explains why the `motion-vendor` exclusion was unnecessary. The `react-vendor` guard directly above uses `/node_modules/react/` and `/node_modules/react-dom/` with trailing slashes. Using `node_modules/motion/` (trailing slash) would align with that precedent and prevent any future false positive from a package coincidentally containing "motion" in its path.
